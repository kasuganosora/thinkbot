---

Telegram で話しかければ、話した内容を覚えています。ディスクや RAID アレイ、デプロイスクリプトにトラブルが起きると、向こうから先にメッセージをくれます。「これ深刻？」と返せば、そこから会話が続きます。自分専用のサンドボックスでコマンドを実行したり、Web で調べ物をしたり、コードを編集したりして、結果を報告することもできます。

thinkbot は **自分でコントロールできる AI アシスタント** が欲しい人のためのものです。個人開発者、自分でサーバーを運用している人、グループチャットや Fediverse に bot を置きたい人など。`docker compose` コマンド一つで起動でき、データはすべて自分のマシンに残ります。

```text
🤖 [server-1/smartd · INFO] sda と sdb からそれぞれ SMART EmailTest が届きました。
   smartd が通知チャネルをテストしているだけで、故障ではありません。どちらのディスクも正常です。
🙋 うん、テスト中
🤖 了解です。sda と sdb の両方から届いたので、両ディスクのアラート経路は機能しています。
   本当に SMART の問題が出たら、すぐにお知らせします。
```

## thinkbot とは

thinkbot は、聞かれたことに何でも答えるだけのアシスタントではありません。個性があり（それを書くのはあなたです）、これまでの会話を覚えていて、グループチャットでは自然に会話に加わり、サーバーに異常があれば真っ先に知らせに来ます。すべてに返信しようとはせず、**いつもそばにいて、空気を読めて、頼りになるパートナー** を目指しています。

## 主な特徴

- **ヘルプデスク口調ではなく、個性がある**：人格は SOUL.md に書かれていて、話し方や口癖、興味をあなたが決められます。雑談でも、グループでのおしゃべりでも、アラート報告でも同じ口調です。
- **グループチャットに溶け込み、黙るべき時もわかる**：毎回 @ する必要はありません。「チャットのリズム」設定（発言傾向、連投のデバウンス、連続返信の上限）で会話に加わるかを判断します。メンションや返信をされたら必ず応答します。

- **向こうから連絡してくる**：サーバーのアラート、デプロイ結果、頼んでおいたリマインダーが、ログファイルに埋もれず Telegram のチャットに届きます。
- **覚えていて、頼めば忘れる**：階層化された長期記憶で、数週間前の会話も続きから話せます。忘れてと言えば削除し、後から覚え直すこともありません。プライバシーはあなたの手の中です。
- **実際に作業ができる**：bot ごとに専用のサンドボックスコンテナがあり、コマンド実行、ファイルの読み書き、ブラウザ操作、Web 検索やページ取得ができます。スキルや MCP ツールも追加できます。
- **一つのデプロイで、いろんな場所で会話**：Web、Telegram、Misskey、Mastodon が同じ bot を共有し、プラットフォームをまたいで文脈がつながります。一つのデプロイで、それぞれ個性の違う複数の bot を動かせます。
- **モデルを選べる**：OpenAI 互換 API（DeepSeek など）、OpenAI Responses、Anthropic、Gemini。切り替えは Web UI で数クリックです。
- **主導権はあなたに**：セルフホストで、データはローカルの SQLite ファイルに保存されます。ツール権限、利用量の上限、ユーザー管理はすべて Web 管理画面で行えます。

## 対応プラットフォーム

| プラットフォーム | 状態 | できること |
|---|---|---|
| Web | ✅ 利用可能 | 内蔵のチャット UI と管理画面。ツール呼び出しの様子、サンドボックスのターミナルとデスクトップも表示 |
| Telegram | ✅ 利用可能 | 個人チャットとグループチャット（メンションまたは返信）；画像・ファイルの送信；グループ管理ツール（ピン留め、削除、BAN など。ツール権限で有効化）；**サーバーアラートの受信** |
| Misskey | ✅ 利用可能 | メンションへの返信、タイムラインのフォロー；投稿、リアクション、リノート、フォロー、検索、投票 |
| Mastodon | 🚧 開発中 | コードはマージ済み、本番環境ではまだ未テスト。メンションと返信への応答、任意でタイムラインのストリーム；投稿、お気に入り、ブーストなど。インスタンス URL とアクセストークンは Web UI の Bot 設定 → プラットフォームで設定 |

## できること

### 1. サーバーに問題が起きたら、まずあなたに知らせる

smartd、mdadm、cron、バックアップジョブやデプロイスクリプトから `thinkbot-notify` を呼び出すだけです。アラートは bot 自身の言葉で、**普段 bot と話している Telegram のチャット** に届きます。アラートはチャット履歴に保存されるので、続けて質問すれば、bot はどのアラートの話かわかっています。

```text
🤖 [server-1/mdadm · INFO] RebuildFinished on /dev/md/md3 (mismatches found: 140672)
   md3 の定期チェックが完了し、不一致が 140672 件見つかりました。アレイは [UU] のままで、
   両ディスクともオンラインです。急ぎではありませんが、時間のある時に確認をおすすめします。
🙋 対応不要
🤖 了解です。

        …翌日…

🤖 [server-1/mdadm · WARN] RebuildStarted on /dev/md/md3
   md3 がまたチェックを開始しましたが、進捗が 89.6%、0K/sec で止まっています。
   ハングしているようです。確認をおすすめします。

        …その後…

🤖 [server-1/mdadm · INFO] RebuildFinished on /dev/md/md3 (mismatches found: 32384)
   今回は完了しました。不一致は 32384 件に減り、アレイは正常です。
```

デプロイスクリプトも同じです。最後のステップで結果を bot に送り、「エラーあった？」と返せば会話を続けられます。bot は通知の内容をもとに答えます。設定手順：[設定 › notify クイックセットアップ](docs/configuration.md#告警通知notify快速接入)。

> 通知には専用の配信経路があります。bot の「これには返信しない」判断に握りつぶされることはありません。モデルがエラーやタイムアウトになった場合は、元のテキストがそのまま送られます。warn と critical のアラートには必ず元のアラート本文が含まれます。同じアラートは重複排除とレート制限がかかります。現在の配信先は Telegram のみです。

### 2. 複数ステップの作業を任せる

```text
🙋 blog-app のローカルコミットで eslint と vitest を回して、問題なければ push して
🤖 依存関係が足りなかったので、インストールしました。
   ESLint でエラーが 2 件出ましたが、ベースのコミットにも存在していたので、
   別のコミットで修正しました。
   vitest は 1 件失敗していますが、ベースのコミットでも失敗するので今回の変更とは無関係です。
   最初の push は失敗しました。リモート設定を確認して修正し、push しました。
   まとめ：8 ファイル変更、ESLint エラー 0 件、push 済み。
```

コマンドはすべてその bot 専用のサンドボックスコンテナ内で実行され、ホストでは実行されません。

### 3. 出典付きで調べ物をする

```text
🙋 今回は記憶に頼らないで、X の今日のリリースノートを実際に Web で検索して
🤖 見つかりました。公式リリースページに基づいています：… 主な変更点は 3 つです：…
   出典：X の公式リリースノートページ（リンク）
```

`web_search` と `web_fetch` が組み込まれています。検索バックエンドはシステム設定 → 検索で設定でき、バックエンドが失敗したら次のものに自動で切り替わります。

### 4. スキルを使う

```text
🙋 use_skill で code-review スキルを読み込んで、その第一原則を教えて
🤖 読み込みました。第一原則は：…
```

スキルは `SKILL.md` ファイルを含むフォルダです。`skills/` に置くか、管理画面から追加します。

### 5. あなたを覚えていて、頼めば忘れる

```text
        …3 週間前…
🙋 いつものコーヒーはオーツラテ、甘さ控えめ
🙋 趣味でちょっとした家計簿アプリを作ってる

        …今日…
🙋 おはよう！今日まず何をするか一緒に考えて
🤖 おはようございます！まずは甘さ控えめのオーツラテ ☕ を飲んでから、家計簿アプリで
   詰まっていたエクスポート機能を仕上げるのはどうでしょう？

🙋 あの週末旅行の計画のことは全部忘れて
🤖 了解です。旅行計画に関する記憶を削除しました。もう話題にはしません。
```

### 6. 一緒に遊ぶ

- **キャラクターとおしゃべり**：Bot 設定 → 人格で SOUL.md（性格、話し方）を書けば、アニメの話でもゲームの話でもそのキャラのままです。
- **テキストアドベンチャーで遊ぶ**：選択肢を出してくれます。Telegram ではボタン、Misskey ではネイティブの投票、Web UI ではカードとして表示されます。
- **画像を見せる**：メインモデルが画像に対応しているか、ビジョンモデルを設定していれば、スクリーンショットやミーム画像を理解できます。スタンプの場合はスタンプに対応する絵文字が見えるので、それに合わせてノってくれます。
- **グループでお手伝い**：メンションや返信をされたら必ず応答します。それ以外でどう会話に加わるかは、下の「グループチャットに溶け込む」を参照してください。

### 7. グループチャットに溶け込む

Telegram のグループに追加すれば、毎回 @ する必要はありません。グループの普通のメッセージも「チャットのリズム」を通り、いくつかを選んで自然に返事をし、残りは聞くだけにします（聞いた内容は覚えておけます）。

```text
🧑 ジェイ：今週末のコミコン、誰か行く？
🧑 リン：行く！でもまだ誰のコスプレするか決めてない
🤖 リン、去年のロボットアニメのヒロインはどう？小道具が作りやすいし、やってる人もほとんどいないよ
🧑 ジェイ：笑 こういうのも知ってるんだ
🧑 リン：@thinkbot ウィッグ持っていったほうがいい？
🤖 持っていこう。汗をかき始めたら、地毛が真っ先に崩れるから
```

Bot 設定 → プラットフォーム → チャットのリズムで、チャットの種類（個人 / グループ / チャンネル）ごとに調整できます：

- **発言傾向**（0.01–1.0、グループのデフォルトは 0.4）：メンションされていないメッセージに対して発言する確率。1.0 ならすべてに返信します。
- **デバウンスの待機時間**（グループのデフォルトは 3 秒）：連続した複数のメッセージを一つとして扱い、一行ごとに割り込まないようにします。
- **連続返信の上限**（グループのデフォルトは 3）：何ターンか続けて話したら一旦控え、会話を独占しないようにします。
- メンションと bot への返信はこれらの制限を受けず、必ず応答します。個人チャットはデフォルトでリズムがオフ（即時返信）、Web チャットは制限されません。

返信不要なメッセージは自分で判断して、メモするだけにすることもできます。Misskey / Mastodon のタイムライン投稿では、さらに能動的な参加（`engagement.*` 設定、observer / lurker / moderator / active のプリセットあり）を有効にでき、関連度のスコアリングとレート制限を経てから会話に加わります。詳しくは [docs/configuration.md](docs/configuration.md) を参照してください。

### 8. その他の使い方

- **一つのデプロイで複数の bot**：bot ごとに人格、モデル、記憶、サンドボックスコンテナ、プラットフォームアカウントを持ち、互いに混ざりません。
- **一つの bot を複数のプラットフォームで**：同じ bot を Telegram と Misskey で同時に動かせ、片方で話したことがもう片方にも引き継がれます（Mastodon 対応は開発中：コードはマージ済み、本番環境ではまだ未テスト）。
- **リマインダーとスケジュール**：「明日の朝 9 時にリマインドして」と頼んだり、定期ジョブを設定して時間割どおりに動かしたりできます。

## 記憶のしくみ

簡単に言うと、人間と少し似ていて、短期記憶と長期記憶があります：

1. **メモする**：会話の中で覚えておく価値のあることは、まず短期記憶に入ります。短期記憶は約 2 週間で期限切れになります。
2. **整理する**：バックグラウンドジョブが定期的に短期記憶を長期記憶（事実、好み）に変換し、重複をまとめ、古いものを更新します。「夢」を有効にすることもできます。毎晩、最近の記憶を採点し、重要なものは残し、些細なものは薄れさせ、ついでにあなたについてのイメージを更新します。
3. **思い出す**：返信する前に、今の話題に関連する記憶を意味の近さで探し出します。だから数週間前に話した趣味も、関連する話題になれば自然と出てきます。
4. **忘れる**：何かを忘れるよう頼むと関連する記憶が削除され、後から覚え直さないよう印が残されます。管理者は Bot 設定 → 記憶で個々の記憶を確認・削除することもできます。

長い会話は自動的に要約に圧縮されるので、そのまま会話を続けられます。管理者は `/compact` で現在の会話を短くしたり、`/clear` で最初からやり直したりもできます。詳しくは [docs/memory.md](docs/memory.md) を参照してください。

## クイックスタート

必要なもの：Docker（`docker compose` プラグイン v2.24 以降を含む）が入ったマシン、モデルプロバイダーの API キー、そして（任意で）[@BotFather](https://t.me/BotFather) から取得した Telegram bot トークン。

**1. ダウンロードして設定を準備する**

```bash
git clone https://github.com/kasuganosora/thinkbot.git && cd thinkbot
cp .env.example .env
mkdir -p data/container logs/container
```

`.env` のデフォルト値はそのまま使えるので、編集は不要です。

**2. 最初の管理者アカウントを設定する**（自分のパスワードを使ってください。6 文字以上）

```bash
cat > docker-compose.override.yml <<'YAML'
services:
  thinkbot:
    environment:
      AUTH_BOOTSTRAP_ADMIN: admin
      AUTH_BOOTSTRAP_PASSWORD: change-me-please
    # The default port mapping "8080:8080" is open to your LAN / the internet.
    # Keep these two lines to allow access from this machine only:
    ports: !override
      - "127.0.0.1:8080:8080"
YAML
```

> `!override` には Docker Compose v2.24+ が必要です。これがないと、override の `ports` はデフォルトの `8080:8080` を置き換えずに **マージ** され、ポートが衝突します。リモートからアクセスする必要のあるサーバーで動かす場合は、`ports` の 2 行を削除し、リバースプロキシやファイアウォールで保護してください。

**3. 起動する**

```bash
docker compose up -d --build
```

初回のビルドには数分かかります（権限エラーが出た場合は `sudo` を使うか、ユーザーを `docker` グループに追加してください）。`docker compose ps` に `healthy` と表示されれば準備完了です。

**4. Web UI でセットアップを完了する**

`http://localhost:8080` を開き、上のアカウントでログインしてから：

1. **システム設定 → モデルサービス**（系统设置 → 模型服务）：プロバイダーを追加し、API キーを入力し、モデルを追加して、**プロバイダーの有効（启用）スイッチをオンにします**。新しいプロバイダーは無効の状態で作成され、無効なプロバイダーで bot を起動すると `LLM "…" not found in config` で失敗します。
2. **システム設定 → Bots → 新規 Bot**（新建 Bot）：bot を作成し、メインモデルを選びます。
3. **Bot 設定 → プラットフォーム**（平台）：Telegram を追加し、bot トークンを貼り付けて有効にします。ページ上部の状態が実行中（运行中）になっていることを確認してください。新しい bot は停止状態で作成されるので、クリックして有効にします。初回起動時に bot のサンドボックスイメージ（約 1.4 GB）がビルドされ、1〜2 分かかります。
4. **ユーザー設定 → 認証コードを生成**（用户设置 → 生成授权码）：`TB-XXXX-XXXX` のコードを Telegram の bot に送ってアカウントを連携します。アラートの受信にはこの手順が必要です。

さあ、Telegram で挨拶してみましょう 👋 Web UI でそのまま話しかけても OK です。

> Web UI は現在、簡体字中国語のみです。上の括弧内が中国語のラベルです。ログイン後、ユーザー設定 → セキュリティ（安全设置）でパスワードを変更してください。管理者アカウントが作成された後は、override の `AUTH_BOOTSTRAP_*` の 2 行は効果がなくなるので削除して構いません。
